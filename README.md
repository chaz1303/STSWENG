# STSWENG

## Folder map

Initial folder strucutre for now for progress, used `feature/qa-pipeline` framework from QAs

| Path                               | Use it for                                                                                                                                                 | For developers                                                                                                                                                                                                            |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/client/`                      | Everything residents see and tap in the app e.g. the screens, buttons and forms.                                                                           | React 19 + Vite root (stack for now) (`index.html`, `main.jsx`, `App.jsx`). Builds to `dist/`.                                                                                                                            |
| `src/client/steps.js`              | The list of screens in the booking journey, from Register to Complete Service.                                                                             | Happy-path step array (`path`, `title`, `story`). `App.jsx` switches on `location.hash`; no router yet.                                                                                                                   |
| `src/client/public/`               | What lets people install the app on their phone's home screen, plus the app icon.                                                                          | Copied as-is to `dist/`: `manifest.webmanifest`, `sw.js` (network-first cache, skips `/api`), `icon.svg`. SW registers in production builds only.                                                                         |
| `src/server/`                      | The behind-the-scenes part the app talks to when it saves or loads anything.                                                                               | Express 5. `app.js` exports the app without `listen()` (used by Supertest and mounted in the Vite dev server); `index.js` listens on `PORT`.                                                                              |
| `src/server/db.js`                 | The one doorway to the database we share with Team 2. We haven't picked the database yet.                                                                  | `getDb()` reads `DATABASE_URL` and throws until a driver is added. No ORM; engine is still open with Team 2.                                                                                                              |
| `src/services/`                    | The rules of the business, like what a booking costs or when it can be cancelled.                                                                          | Domain logic. Included in coverage (70% lines minimum).                                                                                                                                                                   |
| `src/utils/`                       | Small helpers the rest of the code reuses.                                                                                                                 | Pure helpers. Included in coverage (70% lines minimum).                                                                                                                                                                   |
| `src/utils/contract.js`            | What both teams' apps must match: the three service types, how long each takes, and the steps a booking goes through. Don't change it without Team 2's OK. | `SERVICE_TYPES`, `BOOKING_TYPES`, `BOOKING_STATES`, `TRANSITIONS`, `INITIAL_STATE`, `canTransition()`. Values follow `userStories.pdf` p.2; asserted by `tests/unit/contract.test.js`.                                    |
| `mobile/`                          | The phone app version of Mang Juan. The team opens it in Expo Go to try the screens on a real phone.                                                       | Expo SDK 58 + React Native in TypeScript, with its own `package.json`. Inside `mobile/`: `npm install`, `npx expo start` (scan the QR code with Expo Go), `npx tsc --noEmit` to type-check. Not checked by `ci.yml` yet.  |
| `mobile/screens/`                  | The screens of the phone app, from sign-up to rating.                                                                                                      | `Onboarding`, `Home`, `Book`, `After`. Each screen gets an `app` prop (state + navigation) typed in `types.ts`; `App.tsx` keeps a simple screen stack.                                                                    |
| `mobile/services/`                 | What the phone app asks the back end for: sign-in, bookings, Manongs, payments, account.                                                                   | One file per area (`auth`, `bookings`, `manongs`, `payments`, `account`). Every function is `async` and returns the shape a real API should. Today they return mock data; each spot to wire up is marked `TODO(backend)`. |
| `mobile/mocks/`                    | Pretend data for the phone app until the real back end exists.                                                                                             | Catalog and prices, the mock resident (Bruce Wayne) and his history, and `flags.ts`, which the in-app Dev menu flips to show failure cases.                                                                               |
| `mobile/config.ts`                 | Settings for the phone app, like where the back end lives.                                                                                                 | Reads `EXPO_PUBLIC_*` values from `mobile/.env` (copy `mobile/.env.example`). These ship inside the app, so no secrets. `EXPO_PUBLIC_DEV_TOOLS=1` shows the Dev menu.                                                     |
| `mobile/types.ts`                  | The shape of the app's data (a booking, a user, an address).                                                                                               | Shared TypeScript types for the mock and the screens; a real API should return the same shapes.                                                                                                                           |
| `tests/unit/`                      | Quick automatic checks that the business rules give the right answers.                                                                                     | Vitest, `*.test.js`. CI phase 4 runs `npx vitest run tests/unit --coverage`.                                                                                                                                              |
| `tests/integration/`               | Checks that the app and its back end talk to each other correctly.                                                                                         | Vitest + Supertest against `app.js`, `*.test.js`. No DB yet. Runs in `npm test`; CI phase 5 is a stub.                                                                                                                    |
| `tests/e2e/`                       | Tests that click through the app in a real browser, the way a resident would.                                                                              | Robot Framework + SeleniumLibrary, `*.robot`. `npm run test:e2e` builds, starts `vite preview` on 4173, writes reports to `reports/e2e/`.                                                                                 |
| `.github/workflows/ci.yml`         | The robot that runs all the checks every time someone uploads changes, so mistakes get caught before they're merged.                                       | GitHub Actions. Live: lint, audit, build (uploads `dist`), unit. Contract, integration, e2e and deploy jobs are commented stubs.                                                                                          |
| `.github/pull_request_template.md` | The form you fill in when you ask the team to review your work: which user story it's for, and proof it was tested.                                        | Default PR body: story ID, test evidence, DoD checklist.                                                                                                                                                                  |
| `.env.example`                     | A sample of the private settings each developer needs on their own computer. Real passwords never go in here.                                              | Copy to `.env` (gitignored). Keys: `PORT`, `DATABASE_URL`, `JWT_SECRET`. Loaded by `npm start` via `--env-file-if-exists`.                                                                                                |
| `requirements.txt`                 | The tools a computer needs to install before it can run the browser tests.                                                                                 | `pip install -r requirements.txt`: `robotframework`, `robotframework-seleniumlibrary`. Needs Chrome.                                                                                                                      |
